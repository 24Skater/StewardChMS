Structural Issues

CRITICAL frontend/src/lib/api.ts is 1,986 lines — 2.5× over limit
Every API call for every domain (members, events, giving, accounting, sales, settings, comms…) is packed into one flat file. This makes the file impossible to review in isolation, causes merge conflicts, and defeats tree-shaking.
  • Split into per-domain API modules: api/members.ts, api/events.ts, api/accounting.ts, etc.
  • Keep api/client.ts for the shared fetch wrapper + error types only.
  • Each hook file already has a 1-to-1 domain mapping — mirror that structure here.
CRITICAL In-memory token blacklist won't survive process restarts
backend/src/lib/security.ts stores the logout blacklist in a plain JS array. Any restart (deploy, crash, scaling) clears it — allowing a logged-out token to be replayed. The code itself carries the comment "In production, this should use Redis or database."
  • Add a token_blacklist table in Postgres with (jti, expires_at) and a cleanup job.
  • Or configure an Upstash Redis instance and replace the in-memory set.
HIGH Auth token stored in localStorage (XSS-vulnerable)
frontend/src/lib/api.ts reads/writes auth_token from localStorage. The comment at line 1 acknowledges this is vulnerable to XSS and defers a fix. Meanwhile, the backend already issues httpOnly cookies (steward_session).
  • Stop dual-storing. Remove the localStorage path; let the httpOnly cookie do all auth.
  • The backend's COOKIE_OPTIONS is already correctly configured with secure + sameSite: strict.
HIGH Messaging providers are stubs — no real delivery
providers/messaging/email-stub.ts and sms-stub.ts only console.log. The Phase 4 communications feature (compose message, templates, opt-in) is fully wired but silently discards all outbound messages.
  • Wire up a real email provider: SendGrid, Postmark, or Amazon SES via their Node SDK.
  • Wire up a real SMS provider: Twilio or similar.
  • Keep stubs for test environments; swap via an environment variable (MESSAGING_PROVIDER=stub|sendgrid).
HIGH steward-brand dependency loaded from GitHub URL
frontend/package.json declares "steward-brand": "github:24Skater/steward-brand#main". This pins to a branch tip, not a commit hash or tag — meaning the dependency silently updates whenever someone force-pushes to main on that repo.
  • Pin to a specific commit SHA: "github:24Skater/steward-brand#<sha>".
  • Or publish the package to npm (even a private registry) so it gets a lockfile-safe version.
MEDIUM vite listed in backend production dependencies
backend/package.json has "vite": "7.3.1" under dependencies, not devDependencies. Vite is a dev-time build tool; it has no role at runtime and adds ~4 MB to the production install. Move it to devDependencies.
MEDIUM Sparse test coverage — 25 backend + 11 frontend test files for 168 source files
Route-level integration tests exist for the most critical paths (auth, members, events, accounting, sales), but most route files have no test file. The frontend has only component-level smoke tests.
  • Backend coverage target: add test files for worship-plans, messages, kids-checkin, online-giving, groups.
  • Frontend: add hook-level tests using msw or vitest mocks alongside the existing RTL component tests.
LOW reports.ts (612 lines) — should be split by domain
The reports route bundles attendance, giving, membership, finance, and sales report endpoints together. Each report type is independent; extract into routes/reports/attendance.ts, giving.ts, etc., then re-export from an index.
LOW frontend/dist/ present on disk but not tracked in git
The frontend/dist/ directory exists locally but is correctly excluded from git via .gitignore. No action needed — just confirming it's clean.

Recommendations — Prioritized

1 · Split api.ts immediately

The 1,986-line monolith is the single biggest maintenance liability. Split into ~10 domain API files this sprint. Hooks already provide the right split structure to follow.

2 · Fix token blacklist for production

Before real users log in, replace the in-memory blacklist with a Postgres table or Redis. A user whose session is terminated can still replay their token until the server restarts.

3 · Consolidate auth storage

Remove localStorage token storage; rely solely on the httpOnly cookie already being set. This eliminates the XSS risk at minimal effort since the backend infra is already correct.

4 · Wire real messaging providers

Add MESSAGING_PROVIDER env var. Implement SendGrid (email) and Twilio (SMS) adapters. Keep stubs for test environments. Communications feature is complete but currently silent.

5 · Pin steward-brand to a commit SHA

Change "github:24Skater/steward-brand#main" to a specific commit hash. This prevents silent upstream changes from breaking your builds.

6 · Move vite to devDependencies in backend

One-line change in backend/package.json. Keeps the production Docker image lean.

7 · Expand test coverage

Add backend integration tests for: worship-plans, messages, kids-checkin, online-giving, groups. Target 80% route handler coverage.

8 · Split reports.ts and useAccounting.ts

Both files bundle multiple domains. A low-risk refactor that pays off when teams start working on reports or accounting features in parallel.
